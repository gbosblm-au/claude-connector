# claude-connector v13.9.0

Tutoring Homework Upload and Assessment Spec v1.0.0 — Section 6.

A defect fix in the docx reader, found by testing the place students actually
write their answers.

---

## Text boxes and content controls

### The question that prompted this

Does the reader pull text out of text boxes and content controls, or only out of
body paragraphs and tables? On a worksheet with answer boxes, the student's
answer sits in `<w:txbxContent>` or a content control's `<w:sdtContent>` — not
in a body paragraph.

**Answer: it already did.** The run scan is global rather than scoped to
`<w:body>`, so both were being read. Verified against a constructed fixture
rather than by reading the code, because "it looks like it should work" is not
evidence.

### But it read them TWICE

Word 2010+ writes a text box twice: once under `<mc:Choice Requires="wps">` as
DrawingML, and again under `<mc:Fallback>` as legacy VML, with the same text in
both. A global run scan sees every text-box answer twice.

This is not cosmetic:

- A **labelled** answer survived by luck. An explicit `Answer:` label replaces
  whatever was inferred before it, so the second copy overwrote the first with
  the same value.
- An **unlabelled** answer did not. The two runs concatenated into `"36 36"`,
  which is marked wrong — the student is told their correct answer was
  incorrect.

Confirmed before the fix was written:

```
TEXT:         "1. What is 15% of 240?\n36\n36"
BLOCK ANSWER: "36 36"
```

### The fix

`<mc:AlternateContent>` is resolved before anything else. The OOXML rule is that
a consumer which understands the Choice requirement uses the Choice and ignores
the Fallback; text extraction understands both equally, so Choice wins.

Fallback is dropped **only when a Choice is present**. An AlternateContent
carrying only a Fallback still has its content read — dropping it
unconditionally would lose the answer outright, and that is the worse failure: a
duplicated answer is visibly odd, a missing one reads as a student who did not
attempt the question.

## Tests

`npm run test:homework` — **62 passed, 0 failed, 0 skipped** (was 59).

Three new cases: a real fixture containing both a text box and a content
control, the AlternateContent duplication, and the Fallback-only path.

The text-box fixture cannot be produced by python-docx, so the document part is
rewritten directly in the fixture builder — the same lesson as the table-cell
rule two releases ago. **A fixture generated by a tidy library exercises the
tidy path only.** Anything that only appears in messy real-world output needs a
document constructed by hand.

Mutation-tested: removing the AlternateContent resolution fails 2; dropping
Fallback unconditionally fails 1.

### Regression

`npm run test:voice-all` — 286 passed, 0 failed, unchanged.
